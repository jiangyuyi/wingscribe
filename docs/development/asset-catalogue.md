# 原片与任务存储契约

B4a，2026-10-19。实现入口是 `src/storage/catalogue.py`。当前只提供显式启用的存储层，扫描器、Web 与 TaskManager 尚未调用它，也没有迁移用户的实际数据库。接入与恢复步骤见[执行记录](execution-log.md)。

## 数据关系

| 表 | 职责与唯一性 |
| --- | --- |
| `asset_sources` | 来源 ID 与当前根目录绑定；重新绑定根目录保留 ID，不访问 NAS |
| `assets` | 原片逻辑位置；同一 `source_id + path_key` 只有一条记录 |
| `asset_versions` | 文件大小、纳秒修改时间、带算法名指纹、尺寸及拍摄时间；同一原片保留递增版本 |
| `analysis_runs` | 绑定某一文件版本，保存模型、参数快照、分类版本、结果类型与错误；同版本的 `run_key` 幂等 |
| `detections` | 分析中的鸟体框、检测置信度、结果 JSON 和可选输出路径；一张原片可以对应多个框 |
| `processing_jobs` | 任务请求键、参数快照、状态和错误字段；相同请求键不重复创建 |
| `job_items` | 绑定任务与文件版本，预留状态、原因、错误和尝试次数；同任务同版本不重复入队 |
| `asset_schema_migrations` | 独立 schema 版本，不占用全库 `PRAGMA user_version` |

这套表不改变 `photos` 的人工标签、AviList 或扫描历史。旧输出与新原片的关联将在 B4b 接入时明确建立，本批没有推断或回填历史原片。

## 身份与版本

按当前 Windows 使用环境，根目录及相对路径的比较键统一大小写，保留显示路径。拒绝绝对照片路径、父目录跳转、空片段、`.`、流语法及尾部点/空格。这里只校验逻辑路径；实际文件访问仍必须使用 B1 的路径边界检查，不能用这里的字符串检查替代链接越界检查。

映射盘与 UNC 别名不会被自动认定为同一来源。盘符变化通过 `rebind_source` 明确重新绑定；与已有来源冲突时拒绝合并。当前不支持区分仅大小写不同的 NAS 文件名。

重复观察到相同大小、mtime_ns 和指纹时复用当前文件版本；三者任一变化即新增版本。旧任务与旧分析继续引用原版本，不能自动解释为新版分析。指纹由调用方提供，必须带算法名，例如 `sha256:...` 或明确命名的部分指纹算法；存储层不读取照片，也不保证调用方指纹的强度。不同位置即使指纹相同也保留为独立原片。

版本中的拍摄信息是首次登记快照；重复登记不会补写已存版本的元数据。后续扫描应在登记前完成可用信息采集；无法读取文件时的登记策略在 B4b 实现，不伪造哈希或尺寸。

## 事务与升级

构造 `AssetCatalogue(db_path)` 不产生 IO。调用 `initialize()` 才建立增量结构；已有数据库首次升级必须提供备份目录。迁移持有 SQLite 写事务，先生成一致性备份并检查完整性，再逐条执行建表。错误回滚整批 DDL；成功后重复初始化不重复备份或迁移。未知版本或已标记完成但缺表的数据库会被拒绝，不能静默补成空表。

`transaction()` 为每次操作建立独立连接，启用外键并使用 `BEGIN IMMEDIATE`。来源、原片、版本和入队等相关写入可以一次提交；异常退出整体回滚。调用方不要吞掉数据库写入异常后继续提交。读操作也使用短连接。SQLite 提供跨实例写事务仲裁；这尚不等于模型工作进程互斥或完整任务租约。

`record_analysis` 保存不可变结果：`succeeded`、`no_detection`、`quality_filtered`、`failed`。未检出只是模型结果，不能视为确实无鸟。失败必须保留错误原因。相同幂等键、相同内容返回已有记录；同键不同内容明确拒绝，不覆盖旧结果。不同重试应使用新的分析运行键。

任务当前只支持创建、去重入队和读取，初始状态为 `pending`。状态迁移、领取、租约、重试、崩溃恢复，以及源不可用状态更新都留给后续子批；不能直接修改状态字段来宣称这些流程已实现。

## 验证范围

`tests/test_asset_catalogue.py` 覆盖迁移幂等与回滚、备份、旧标签保留、版本变化、多来源同名、来源重绑定冲突、外键、分析与任务幂等、多鸟关系及独立实例并发登记。B3f 真实验收库的副本也已演练升级，原有所有表逐行比较一致。实际 NAS 断线和进程恢复尚待 B4c/B4d，当前不改真实照片或主数据库。
