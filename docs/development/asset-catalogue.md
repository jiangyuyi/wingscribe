# 原片与任务存储契约

B4a–c，2026-10-19。存储入口是 `src/storage/catalogue.py`，扫描观察入口是 `src/storage/scan_observer.py`。流水线初始化时建立增量表，已有库先备份到数据库同目录的 `backups/`；两种扫描入口通过同一原片处理函数登记结果。`pipeline_jobs.py` 管理扫描执行会话，TaskManager 关联持久任务并恢复上次状态。本轮只运行隔离验收库，没有迁移用户实际主库。执行步骤见[执行记录](execution-log.md)。

## 数据关系

| 表 | 职责与唯一性 |
| --- | --- |
| `asset_sources` | 来源 ID 与当前根目录绑定；重新绑定根目录保留 ID，不访问 NAS |
| `assets` | 原片逻辑位置；同一 `source_id + path_key` 只有一条记录 |
| `asset_versions` | 文件大小、纳秒修改时间、带算法名指纹、尺寸及拍摄时间；同一原片保留递增版本 |
| `asset_observations` | 每次观察的结果、原因和错误；读取失败时允许没有文件版本，观察键幂等 |
| `analysis_runs` | 绑定某一文件版本，保存模型、参数快照、分类版本、结果类型与错误；同版本的 `run_key` 幂等 |
| `detections` | 分析中的鸟体框、检测置信度、结果 JSON 和可选输出路径；一张原片可以对应多个框 |
| `processing_jobs` | 任务请求键、参数快照、状态和错误字段；相同请求键不重复创建 |
| `job_items` | 绑定任务与文件版本，预留状态、原因、错误和尝试次数；同任务同版本不重复入队 |
| `asset_schema_migrations` | 独立 schema 版本，不占用全库 `PRAGMA user_version` |

这套表不改变 `photos` 的人工标签、AviList 或扫描历史。新分析通过检测记录中的绝对输出路径关联本次归档；没有推断或回填历史原片。旧库只有部分指纹的照片首次扫描仍需建立完整原片版本并重新处理，不把旧输出猜测为已验证的新分析。

## 身份与版本

按当前 Windows 使用环境，根目录及相对路径的比较键统一大小写，保留显示路径。拒绝绝对照片路径、父目录跳转、空片段、`.`、流语法及尾部点/空格。这里只校验逻辑路径；实际文件访问仍必须使用 B1 的路径边界检查，不能用这里的字符串检查替代链接越界检查。

映射盘与 UNC 别名不会被自动认定为同一来源。盘符变化通过 `rebind_source` 明确重新绑定；与已有来源冲突时拒绝合并。当前不支持区分仅大小写不同的 NAS 文件名。

重复观察到相同大小、mtime_ns 和指纹时复用当前文件版本；三者任一变化即新增版本。旧任务与旧分析继续引用原版本，不能自动解释为新版分析。指纹由调用方提供，必须带算法名，例如 `sha256:...` 或明确命名的部分指纹算法；存储层不读取照片，也不保证调用方指纹的强度。不同位置即使指纹相同也保留为独立原片。

版本中的拍摄信息是首次登记快照；重复登记不会补写已存版本的元数据。`discover_asset` 只登记逻辑位置，新原片可用性为 `unknown`，不会伪造哈希、尺寸或文件版本。读取失败可保存不带版本的观察；恢复读取后，`register_asset` 复用原片身份并登记真实版本。读取新内容失败时不能把失败附会到旧文件版本。扫描器在工作线程读取文件前调用它。

扫描范围内被提交处理的 JPEG 使用完整 SHA-256、大小和纳秒修改时间建立版本；读取哈希前后及处理结束核对大小与修改时间。相同版本、模型名称、名录版本、处理参数、候选列表摘要及输出配置已有正常结果，且已关联输出仍存在时，记录明确跳过原因。未检出及质量过滤也能复用；失败会重试。仅替换同路径权重而不改变配置不会自动失效，重新处理策略仍需后续扩展。

一张照片可保存多个框、置信度、质量信息、识别候选与输出路径。新归档文件名添加本次处理标识，防止不同来源、版本或重试覆盖旧输出。归档中途失败时保留已产生的路径作为失败证据；文件系统写入与两个数据库记录阶段不是一个跨系统事务，完整恢复留给 B4c/B4d。正常去重不检查输出内容哈希，删除输出会触发重新处理。

目录未能遍历、日期范围外及停止后尚未提交的项目不在完整登记保证内。B4d-1 已将来源不存在或目录遍历异常写为任务与扫描历史失败；不再吞掉异常后显示正常完成。不得用当前记录数证明 NAS 扫描完整，也不得将未检出解释为照片确实无鸟。

失败扫描范围内已有原片保留身份与历史，来源不存在时记 `unavailable`，权限/其他遍历错误记 `unknown`；不会推断删除，也不改同来源的范围外原片。故障范围按本次选定扫描目录计算，子目录错误可能让本次整个选定范围的可用性变为未知，这是保守状态，不等于所有照片不可读。成功读取并登记版本后恢复该原片为 `available`，不会仅因根目录恢复就批量宣称所有旧原片可读。文件在版本读取前消失或不可读时分别更新该原片为不可用/未知，不把输出归档故障当成源文件离线。

严格遍历只用于流水线，非扫描调用保留 `LocalProvider` 的原默认行为。扫描显式逐层枚举并上抛权限/IO 错误，排除输出目录、隐藏和系统目录；不跟随目录符号链接或 Windows 重解析目录，以免循环或别名重复。日期裁剪入口使用同一严格枚举方式。故障状态更新只按逻辑来源/相对目录操作数据库，不依赖离线 NAS 路径解析。显式来源重绑定仍由存储接口完成，尚无可视化重绑定向导。

`record_observation` 校验文件版本属于该原片、分析属于该版本；失败必须带错误，跳过必须带原因，成功、未检出和质量过滤必须带版本。相同观察键及内容幂等，同键不同内容拒绝；发现路径本身不改变已有可用性状态。

## 事务与升级

构造 `AssetCatalogue(db_path)` 不产生 IO。调用 `initialize()` 才建立增量结构；已有数据库首次升级必须提供备份目录。迁移持有 SQLite 写事务，先生成一致性备份并检查完整性，再逐条执行建表。错误回滚整批 DDL；成功后重复初始化不重复备份或迁移。未知版本或已标记完成但缺表的数据库会被拒绝，不能静默补成空表。

当前 schema 为 2：新库一次事务建立版本 1 和 2；版本 1 的库先备份，再原子增加观察表和版本标记。升级失败保留原版本 1，不会留下半建的观察表。

`transaction()` 为每次操作建立独立连接，启用外键并使用 `BEGIN IMMEDIATE`。来源、原片、版本和入队等相关写入可以一次提交；异常退出整体回滚。调用方不要吞掉数据库写入异常后继续提交。读操作也使用短连接。SQLite 提供跨实例写事务仲裁；这尚不等于模型工作进程互斥或完整任务租约。

`record_analysis` 保存不可变结果：`succeeded`、`no_detection`、`quality_filtered`、`failed`。未检出只是模型结果，不能视为确实无鸟。失败必须保留错误原因。相同幂等键、相同内容返回已有记录；同键不同内容明确拒绝，不覆盖旧结果。不同重试应使用新的分析运行键。

`src/storage/job_session.py` 提供独占执行会话；B4c-2 已接入日期、文件夹和单图处理入口。会话以数据库旁的 `.worker.lock` 文件持有 OS 排他锁，覆盖扫描和工作线程结束，进程退出自动释放；不得删除锁文件，否则可能使两个进程锁住不同文件。当前约束为 Windows 本地数据库，照片可在 NAS；不支持将数据库放在网络文件系统或通过硬链接等不同数据库路径共享同一锁域。不同数据库使用相同输出目录也不在此锁保护内。

会话开启后、启动工作前显式调用 `recover()`，将上次遗留的运行中任务及其待处理/运行中项目标为 `interrupted`，保留已完成、跳过和失败项目。不会自动处理照片或恢复旧任务为运行态。`start()` 同时只允许一个运行任务；`enqueue()` 幂等，`claim()` 在 SQLite 写事务中领取一个待处理项并增加尝试次数。终结项目须先领取；跳过须原因，失败须错误。任务正常完成要求所有项目完成或跳过，停止和失败收尾须先等待运行项目结束，再将未开始项标为中断。

`retry()` 是存储层接口，为失败、停止或中断任务的失败/中断版本创建新任务，参数保留原任务引用，旧历史不变；它自身不执行照片，也不作为 Web 的盲目续跑入口。产品中的继续方式是重新发起原范围扫描：重新核验当前文件版本，复用有效结果，失败项重新处理。没有可用文件版本的读取失败同样重新扫描，不伪造版本入队。旧任务始终保留原状态。

每次扫描仅有一个照片工作线程使用模型，同时最多保留 4 个未收集结果的 Future；生产者达到上限后等待完成项。目录项目前仍按单个来源收集列表，不能据此宣称整个扫描内存恒定。文件版本验证完成后才持久入队，并按该项 ID 领取，重叠文件夹不会重复执行同一版本。停止后已提交但尚未推理的项目只登记停止观察，留为待处理项，再统一标为中断。主线程等待全部工作结束后才终结任务、释放锁；异常收尾将遗留运行项标中断并将任务标失败。

任务 ID 通过回调传给 TaskManager，状态接口新增 `job_id`、`recovered_jobs`、`persisted_job`。使用配置快照构造新的 TaskManager 时，若能取得同库锁，就恢复遗留状态并显示最近任务；若别的执行者仍持有锁，不抢占或改写其任务。当前管理器不能跨实例停止另一个执行者。重启后的计数来自已持久化任务项，不包含崩溃前尚未完成版本读取的内存队列。观察键带任务 ID 前缀，便于追踪没有版本的读取失败；这类失败仍令整个任务失败。

## 验证范围

`tests/test_asset_catalogue.py` 覆盖迁移幂等与回滚、备份、旧标签保留、版本变化、多来源同名、来源重绑定冲突、外键、分析与任务幂等、多鸟关系及独立实例并发登记。B3f 真实验收库的副本也已演练升级，原有所有表逐行比较一致。进程中断已用真实子进程验证，B4d-1 用临时目录移走/恢复和权限故障注入验证不可用状态与来源重绑定；没有主动断开真实 NAS、修改映射盘或主数据库。真实 SMB 断连时序和网络超时尚未实机验证。

`tests/test_asset_observations.py` 补充读取失败、恢复后的身份延续、旧版本隔离、关联一致性、结果证据要求、观察幂等、版本 1 升级备份及失败回滚。`tests/test_scan_observer.py` 验证两个扫描入口、重复扫描、内容和参数变化、多来源、多鸟、质量过滤、读取/检测/裁切/识别/元数据失败，以及输出保留和缺失后重新处理。
