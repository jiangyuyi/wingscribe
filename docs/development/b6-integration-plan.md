# B6 正式选片流程接入计划

2026-10-21：用户要求回到主线，按可独立验证的小批次继续。B5 的离线算法与三模式已可用，但准确率未校准；本阶段不以校准完成为前提冒充可靠失焦判断。

1. **B6a（本批）：存储边界。** 同一本地 SQLite 中新增独立选片表和迁移版本，依赖 B4 原片版本。保存不可变分析报告及明确版本映射、人工 keep/undecided/reject 和备注、全局默认模式及分析组覆盖。默认 safe；组覆盖可删除以恢复跟随。人工标记绑定文件版本，不自动继承到被替换的新照片。重算只增加快照，不覆盖人工决定。已有数据库先备份，迁移事务化、可重复；不触碰真实用户数据库。
2. **B6b：应用服务与任务。** 原片扫描/登记 → 只读 JPEG 分析 → 候选分组/模式结果 → 原子保存快照。持久任务进度、失败、取消、恢复；禁止沿用归档裁切图作选片输入。建立缓存键与模型/算法/参数版本关系，结果绑定完整文件哈希。
3. **B6c：Web 接入。** 新选片入口、任务状态、并排比较、三模式和全局默认设置、人工决定保存。统一使用 B6a 仓储和 B6b 服务；模式变化不改人工标签。浏览器验收和隔离真实 JPEG 验证。
4. **B6d：人工调整。** 分组合并/拆分、主体切换，保留来源、历史和重算影响；不让旧建议覆盖人工结果。
5. **B6e：文件操作另行确认。** 隔离目录、恢复、删除及衍生图处理方式在实施前确认；此前 reject 仅是数据库标记。
6. **B7：发布收口。** 更新锁定安装器、迁移/备份说明、CPU/GPU 干净环境与 NAS 实机验收。云端在线验证继续跳过并标记。

B6a 验收：已有库迁移备份可读且旧记录不变；重复快照幂等、冲突拒绝；未知文件版本及哈希不匹配拒绝；整批失败回滚；重算后人工标签不变；新文件版本不继承旧判断；模式覆盖优先级与重启后持久化；不执行文件删除或照片改写。

## B6a 完成记录

`src/storage/culling.py` 新增 `CullingStore`，使用独立 `culling_schema_migrations`，明确要求先初始化 B4 catalogue；与旧表同库但独立迁移，首次新增前强制提供备份目录并校验备份。构造不进行 IO，服务未接入前不会自动迁移用户库。

分析快照按 run_key 幂等，完整 JSON 与版本映射共同计算 payload hash；同键不同结果拒绝。所有输入必须且仅能属于一个组，映射到不同已注册版本，并逐一匹配完整 SHA-256。人工决定仅显式写入版本级表，重算无写入权限逻辑，不将未选最佳照片转换为拒绝。全局模式默认 safe；组覆盖绑定快照与组，清除覆盖恢复跟随全局；重算产生新快照时不猜测新旧组对应关系。

11 项新增持久化测试与 catalogue / mode 回归共 49 项通过，5 条原有 Pydantic 弃用警告。初次测试受默认临时目录权限影响无法建测试目录，指定工作区 TEMP/TMP 后全部通过。覆盖迁移备份、迁移异常回滚、保存失败回滚、双写者幂等、未知/错误哈希、标签独立和模式重启持久化。

隔离实测 `.codex-tmp/b6a-validation/result.json`：第三轮模式报告 12 张副本先核验 SHA-256，登记到临时 catalogue，保存/重复保存/重开完整报告一致，默认/组覆盖持久化及恢复继承通过。未导入任何人工判断到正式库，未读写用户数据库或修改照片。仓储目前是可信内部接口，不应直接暴露为任意 JSON 写入 HTTP 接口；B6b 负责标准化分析结果构造，B6c 再加请求校验和路径边界。
