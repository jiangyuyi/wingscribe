2026-10-22，用户确认：对明确标为“拒绝”的原片，移入同一照片来源内的可恢复隔离目录，执行前预览清单。无需再次询问产品方式；开发验收仅使用隔离副本，真实照片执行由用户在页面审阅后点击。

## 分批顺序

1. B6e-1 预览契约：服务从保存的快照及人工决定构建清单，逐项核验当前来源、版本 SHA-256 和普通文件路径。展示原路径、目标路径、大小与不可执行原因。保留/未决定永不进入可执行清单；算法建议不是删除授权。此批不移动任何文件。
2. B6e-2 持久操作记录及移动/恢复：显式迁移前备份；与选片/归档共用工作锁；先持久化意图再执行逐项移动，记录成功/失败。执行重新核验人工决定、来源、版本与目标冲突，过期预览必须重新生成。恢复不覆盖已有文件。中断后根据双方存在状态与哈希恢复记录，双方均存在或均不存在时停止该项并显示冲突，禁止猜测删除。
3. B6e-3 页面：已保存拒绝标记→预览→明确执行；展示逐项结果及操作历史、恢复预览与恢复按钮。未保存编辑阻止预览，网络重试不能重复移动。界面验收全部使用副本。
4. B6e-4 回归：副本移动/恢复后完整哈希一致；重试、部分失败、中断、改标签/改内容/禁用来源、同名冲突、路径链接、扫描排除和同库互斥。真实 NAS 断连未实测则标记待验收。

## 路径与数据契约

- 固定保留目录 `.wingscribe-quarantine/<operation_id>/<来源内相对路径>`；使用当前启用且包含文件的最具体来源。来源配置重叠时按路径层级确定，不因数组顺序改变目标。嵌套选片登记来源不替代当前配置来源。
- 客户端传快照/版本标识，不允许指定任意绝对目标。拒绝链接、junction/reparse point、来源外路径及隔离区内照片；文件身份必须为已保存完整 SHA-256。
- 隔离区不参与今后的选片或归档扫描，显式将隔离区作为扫描根同样拒绝。
- 原片历史身份、人工标记和归档副本保留；隔离后原路径暂不可用，界面需说明；恢复后原路径继续使用原版本。不得将移动解释为重新生成图片或自动删除归档副本。
- 预览本身不承诺文件可写、不创建照片目录；执行才创建隔离目录。移动不得跨来源、不得覆盖、不得降级为未经核验的复制再删除。首版目标为 Windows 本地/映射 NAS，实际 SMB 中断语义需独立实测。
- 整批不是文件系统事务。成功项保留可恢复记录；失败项清楚显示，不回滚已成功项来掩盖部分结果。磁盘操作和数据库提交之间的断点必须可诊断。

## B6e-2 执行服务契约（2026-10-23）

独立隔离 journal schema v1，初始化先备份、与原片/选片表同库；记录不可变预览和逐项 pending/moving/quarantined/restoring/restored/failed 状态。执行接收快照、操作 ID 和预览哈希；首次执行重新生成并精确匹配预览，再保存意图。重试同 ID 不创建新操作，哈希不同拒绝。共用 JobSession 工作锁，逐项移动期间数据库写事务锁定人工决定；先提交 moving/restoring 状态，再进行文件操作并提交完成状态。

Windows 使用不覆盖目标的同卷 rename，不支持的平台拒绝而不降级复制删除。恢复先预览，只恢复已确认隔离项；原路径冲突或哈希变化不覆盖。崩溃遗留 moving/restoring 项只有单侧存在且哈希匹配才可继续或确认；双方存在/均不存在均为冲突。部分失败保留成功项与错误记录。服务测试完成前不开放页面真实操作。
