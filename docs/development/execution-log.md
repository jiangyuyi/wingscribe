# 分批实施计划与验证记录

本记录接续 [改造方案](modernization-plan-2026-10-16.md)。2026-10-16 用户已批准渐进实施及 AviList 保守迁移；旧数据准备重做，仅保留低成本备份与可解释映射，不建设复杂的历史兼容系统。

## 执行约束

- 文档先合入本地 master，再从主干建立业务分支。每批独立提交，验证通过后进入下一批；失败先归因，不以历史测试数字充当当前结果。
- 测试使用临时目录、模拟识别结果与独立数据库，不运行真实照片归档或删除。
- 物种拆分、合并、歧义记录不自动猜测；保留来源、版本及复核报告。数据库迁移先备份、在副本演练，再应用。
- JPEG 优先，Windows 本地数据库与缓存，允许照片位于 NAS。RAW 留到完整流程可用后单独实施。
- 模型版本更换与工程行为修复分别验证；焦点评分未经样本校准不用于自动删除。

## B3c 任务生命周期与工作目录（2026-10-17）

- 任务启动通过同一把锁原子判定，日期模式与文件夹模式互斥；线程创建失败解除运行标记并保留错误。服务层检查实际启动返回值，不再无条件回复成功。
- 新增 `/api/pipeline/status`，包含任务 ID、`idle/starting/running/stopping/stopped/completed/failed`、首个错误、时间和进度。停止采用协作方式，已开始的工作结束前保持运行状态，不强杀写入线程。
- 管理页轮询明确状态，刷新后能恢复显示；不再用日志关键词判断成功。失败/停止不显示虚假的 100%。日志保留最近 1000 条，用任务 ID 和递增位置处理滚动及新任务，修复推送停滞。
