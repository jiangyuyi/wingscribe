## 本地统一 API

`/api/recognize`（独立服务）和 `/api/recognition/recognize`（Web）通过同一工厂获取适配器。相同配置复用实例，首次有效图片请求才加载模型；每个实例串行推理，推理在工作线程执行，避免阻塞异步服务。

请求必须恰有一个非空图片来源。本地支持路径或纯 Base64，暂不下载 URL；不支持 RAW。模型候选使用经过清单校验的 AviList 全部物种。`china`/`auto` 暂回退全名录并记录警告，不使用未验证的旧地域名单。中文名只是目录中的显示别名。

读取 `recognition.local.model_type`（默认 `bioclip-2`）、`processing.device`、`recognition.hf_mirror` 和 `paths.taxonomy_catalogue_path`。相对名录路径按项目根解析。模型和候选缓存需重启才能可靠刷新；本批不实现热更新。

超时会返回失败，但已经开始的底层模型加载/推理无法被 Python 线程强制终止；锁和临时文件保持到该工作结束。排队请求过期后不会再启动模型推理。空预测和无效结果返回失败，不报告成功空列表。健康检查的 `models_loaded` 只反映本进程统一 API 实例，不能代表独立流水线模型。

现有照片流水线继续使用同步 `predict`/`predict_batch`，本批不改变归档行为、原图写回或模型评分算法。B3c 已处理任务状态与启动竞争，B3f 已补真实模型流程验收，详见[执行记录](execution-log.md)。单张 HTTP 真实测试使用归档裁切，首次请求约 36.3 秒、缓存复用约 32 毫秒；这不是普遍性能保证。真实批量 HTTP、精度基准、NAS 断线恢复仍不能据此宣称通过。
