# Feasibility of an English application interface

**Recommendation.** Keep the existing recognition pipeline and database. Add a Chinese/English display preference to the local Web UI, starting with Settings. The four Jinja pages make the first step small enough to test independently. The largest part of the work is translating messages generated after the page loads, particularly scan errors and culling recovery instructions.

## What needs to change

| Surface | Evidence in 3.0.0 | Proposed treatment |
| --- | --- | --- |
| Page titles, navigation and forms | Gallery, administration, settings and culling each declare a Chinese HTML language. [Templates](../../src/web/templates/) | Use stable message keys and two local catalogues. Render the correct `lang` attribute. Keep layout and controls identical across languages. |
| Settings and native path selection | The backend supplies Chinese labels and descriptions. The template also constructs picker labels, waiting text and errors. [Settings definitions](../../src/web/config_helpers.py) · [Settings page](../../src/web/templates/settings.html) | Pilot the entire first-run journey, including invalid YAML, folder/file selection, cancellation, save and restart. Keep YAML keys and native paths stable. Windows owns system dialog buttons, whose language may follow the OS. |
| Live status, comparison and recovery | Culling JavaScript renders decisions, warnings, partial failures and quarantine history. [Culling UI](../../src/web/static/culling.js) | Share translation keys across templates and JavaScript. Translate status codes at display time. Include singular/plural counts and the item affected by an error. Leave user notes verbatim. |
| Backend errors and progress logs | API responses and processing logs already contain readable messages. [Web API](../../src/web/app.py) · [Processing pipeline](../../src/pipeline_runner.py) | Add a stable message code plus arguments when a message is intended for users. Keep existing response fields for clients and preserve diagnostic detail in logs. Translate new messages at the UI boundary; old logs remain readable in their original language. |
| Species names and archive data | The AviList importer reads English names. Gallery filtering currently uses `primary_bird_cn` and `scientific_name`; manual correction accepts a Chinese name and can update files. [AviList importer](../../src/metadata/avilist.py) · [Gallery and correction routes](../../src/web/app.py) | Look up a display label by scientific identity, prefer the requested common name, then fall back to the scientific name. Extend search to English names. Keep display language independent of recognition prompts, species identity, archive templates and metadata writes. |

## Suggested sequence and acceptance

1. **Settings pilot.** Bundle both catalogues with the app so they work offline. Use a browser cookie for the explicit choice, keeping Chinese as the default. Resolve it per request so two browsers can use different languages. Provide a visible switch even before configuration is valid. Check that refreshing and restarting retains the choice and that switching never saves a partially edited form.
2. **Complete the daily workflow.** Cover gallery, scanning, candidate lists, culling decisions and quarantine/restore. Use locale-aware formatting for visible dates and numbers. Keep API enums, scientific names, stored timestamps and configuration values unchanged. Test long English labels, confirmations, counts, errors, and a partially successful quarantine followed by recovery.
3. **Add species display and search.** Run both locales against the same new and legacy databases. A language switch should produce identical asset IDs, candidates, scores, cache keys, manual decisions, file names and metadata hashes. Check historical or unmatched taxa with a missing English common name. Add a separate opt-in setting later only if users want English names in *new* archive paths or metadata.
4. **Verify distribution.** Test the packed application offline with both languages. Check that the payload allowlist contains the catalogues and that validation errors still make sense after a restart. Treat the installer wizard, CLI and archived logs as separate localization surfaces.

A UI-only release is feasible without a schema migration or model retraining. Bilingual search and metadata authoring need separate acceptance because they touch different parts of the photo workflow. The safest first milestone is a complete bilingual Settings page that works with the stock Windows installer runtime.
