# JPEG 合焦选片功能方案

日期：2026-10-16。状态：需求已部分确认，算法和交互尚待验证；没有实现自动删除。

## 1. 已确认的产品范围

- 个人 Windows 本地运行，可扫描 NAS 上的相机 JPEG。
- 推荐最清晰的照片；明显失焦候选可预览，由用户决定是否删除。
- RAW 暂不支持，单列后续完整链路计划。
- 原图元数据写回策略本轮不调整。

首版推荐以“同一次拍摄/相似主体的一组照片”为单位比较。来自不同场景、不同主体大小的照片，不应简单用一个全局锐度分数排全库名次。独立照片仍可给出清晰度证据和待检查状态。

## 2. 要判断什么

这里的目标是主体细节清晰程度，而非物种识别置信度、构图或曝光总分。从单张照片通常不能可靠区分所有光学失焦、相机抖动、主体运动、降噪涂抹和压缩损伤；界面宜显示“疑似不清晰/疑似失焦”，不能保证知道物理成因。

建议分析结果分别保存：

| 结果 | 用途 |
| --- | --- |
| 鸟体清晰度及有效像素数 | 默认区域基线 |
| 头部/眼部清晰度（有可靠定位时） | 更贴近摄影者保留偏好 |
| 噪声、曝光、遮挡 | 解释异常和降低判断可靠度，不混成一个不可解释的总分 |
| 定位/分析可靠度 | 判断是否应自动推荐，或交给用户复核 |
| 组内排名和近似并列 | 推荐 Top-K；分差不足时允许多张并列 |
| 人工决策 | 保留、待定、拒绝；与算法结论分开保存 |

分析失败、小鸟像素不足、找不到鸟或找不到眼，都不等于失焦，更不能直接进入删除名单。

## 3. 为什么不直接复用当前 quality_score

`src/pipeline_runner.py:process_image` 先通过 `crop_and_resize` 将有 padding 的裁切缩到目标尺寸并保存 JPEG，再计算质量。`src/core/quality.py` 把拉普拉斯方差、Tenengrad、对比度、曝光、检测置信度和鸟占比加权。

2026-10-16 用当前实现做了一个固定种子合成对照（256×256 灰度纹理，无检测分和鸟占比）：

| 输入 | quality_score | 拉普拉斯方差 |
| --- | ---: | ---: |
| 原始纹理 | 0.5854 | 21.03 |
| 高斯模糊纹理 | 0.3622 | 2.56 |
| 同一模糊纹理加入噪声 | 0.8759 | 9707.02 |

构造方式：灰度 `128 + 45*sin(x/3) + 30*sin(y/7)`，模糊 sigma=5，噪声标准差 22、NumPy RNG seed=42，裁到 0–255，PNG 保存后调用现有 QualityEvaluator。此结果仅证明现有分数可被噪声显著抬高，不是鸟片基准，不代表某种新算法已有效。

另外，padding 中的清晰树枝可能压过模糊鸟体；缩放和 JPEG 重编码改变高频信息；小鸟和大鸟的分数不可直接比较。这些问题需要区域和输入协议改造，不能靠调整一个阈值解决。

## 4. 建议的数据流程

```text
登记全部 JPEG 原片与状态
  -> 读取拍摄时间/方向/尺寸，生成可追溯预览
  -> 在缩略图上定位鸟体，映射回原始像素坐标
  -> 形成候选拍摄组，允许人工拆分/合并
  -> 提取原分辨率鸟体区域；有可靠定位时再提取头/眼区域
  -> 独立焦点评估与噪声/曝光检查
  -> 组内推荐 + 无法判断 + 疑似失焦预览
  -> 用户确认保留/拒绝，后续明确执行隔离或删除
```

选片可以在物种识别之前运行，也允许不识别物种直接选片。既有 `legacy_reject` 不得提前剔除选片输入；建立独立分析任务，先保留每个原片记录，才能向用户展示所有候选。

## 5. 候选分组

首版只自动形成高把握的拍摄组：优先结合相机标识、拍摄时间与子秒、目录上下文、相邻画面相似度。文件名只作为弱辅助，物种相同也不足以证明同组。

- 时间缺失或只有秒级时允许用户选择组，不以文件修改时间假装精确连拍时间。
- 默认时间间隔先作为可调参数，必须结合真实拍摄习惯校准；本轮不固定“几秒就是一组”。
- 鸟体移动或连拍姿态改变可仍属一组；突然换主体、切场景则拆组。
- 多鸟场景先让用户确认主要主体；每个检测区域单独保存结果，默认主体选择必须可见。
- 单张照片为独立组；组内全部模糊时显示“本组相对较好，但仍建议检查”，不把第一名强行标为清晰。

## 6. 算法分两步验证

### A. 低成本基线

统一 EXIF 方向和区域坐标，保留原像素分析窗口。比较局部梯度、多尺度高频/边缘、噪声估计等指标，在主体区域聚合，明确记录实际缩放比例和处理步骤。原始尺度与受控归一化尺度分别评测，不能一律放大到固定尺寸后比较。

只在相似组内做相对排序，优先输出可靠度和并列范围。不要将“锐度值归一化到 0–100”称为“合焦概率”。真实概率需要用有标签数据校准。

### B. 学习式补充

使用 PyIQA 的 TOPIQ/MUSIQ 等作为鸟体区域的实验对照，评估是否优于经典基线，尤其检查高 ISO、锐化边缘和复杂背景。它们面向通用感知质量，不天然等同于鸟眼合焦检测。[PyIQA](https://github.com/chaofengc/IQA-PyTorch)、[TOPIQ 论文](https://arxiv.org/abs/2308.03060)。

若真实样本显示“鸟眼清晰”是主要误判来源，再增加小型鸟头/鸟眼定位模型。普通人体 pose 模型不能直接提供鸟眼关键点；首版可先支持用户手动指定头部区域，收集纠错而不承诺自动眼部定位。[Ultralytics Pose 定义](https://docs.ultralytics.com/tasks/pose/)。

不采用生成式补清晰后的图评分，因为它可能改变需要评价的原始细节。

## 7. 界面草案

选片工作区独立于物种校对页：左侧为拍摄组，中部并排显示原图与同主体 100% 细节，底部保留时间顺序缩略图。可在“拍摄顺序/清晰度推荐”之间切换。

每张图显示推荐理由及可靠度，例如“鸟体细节较清楚；眼部未可靠定位”，不只给一个总分。快捷操作为保留、待定、拒绝，支持撤销与左右切换；快捷键具体映射后续确认。

“疑似失焦”是筛选视图，不是默认勾选的删除清单。候选显示原路径、原图细节、多鸟主体和判断原因，用户可保留意外抓拍或有价值的行为照片。

## 8. 删除与 NAS 的实际行为

首个可用版本可只记录拒绝状态；加入实际文件操作时，优先设计可恢复隔离，用户确认后才执行。算法不得直接删除源文件。

- 本地回收站、NAS 厂商回收站、SMB 删除行为不同，不能保证都可恢复。
- 推荐同一存储根下的隔离目录及操作清单，保留相对目录避免同名覆盖；无写权限时只保留逻辑标记。
- 执行前检查源文件身份/大小/时间是否仍匹配分析输入，防止选片之后文件被替换。
- 操作记录包含源/目标、用户确认、结果和恢复信息；断线/磁盘满/半完成时可重试和对账。
- 照片、裁切图、缩略图和数据库存在关联，不自动级联删除全部衍生物，先定义并展示操作范围。
- 永久删除作为单独明确操作，不与“拒绝标记”或“重新评分”绑定。

这些是待实现设计，本轮没有执行任何照片文件操作。

## 9. 验证数据和验收指标

先准备约 30–50 组探索样本确认交互，再扩大到约 100–200 组、1,000–3,000 张的校准与独立测试样本；这些是起步建议，不是保证统计充分的固定规模。优先来自用户常用相机和拍摄条件，图片可保持本地，只保存相对路径/哈希和标注。

标注：组中可接受的最清晰集合、明显不清晰候选、难判断项；允许并列和多主体。校准/测试必须按拍摄事件或日期分组隔离，不能把相邻连拍拆到两边。若只有一位标注者，记录这代表个人偏好，不能泛化为所有摄影者标准。

| 指标 | 解释 |
| --- | --- |
| Top-1 / Top-3 命中人工可接受最佳集合 | 是否真正帮用户选到好片 |
| 疑似失焦候选精确率、清晰片被误标比例 | 误列好片的风险；同时报告召回和候选覆盖率，防止靠不输出任何候选虚增精度 |
| 自动分组正确率 | 不能用错误的组内比较掩盖算法问题 |
| 无法判断率与人工修改率 | 识别能力不足时是否如实暴露 |
| 每组人工选择耗时 | 相较纯时间顺序浏览是否节省时间 |
| p50/p95 耗时、显存/RSS、本地与 NAS 读取量 | 是否适合日常照片量 |

建议首轮目标（待样本基线后调整）：Top-3 命中率至少 90%，疑似失焦列表精确率至少 95%，并报告分组置信区间与实际覆盖率。任何数值都不是本轮达到的结果；未达目标则保留辅助排序/手动预览，不开放强结论或默认批量操作。

重点反例：高 ISO、小鸟、遮挡、树枝比鸟清楚、眼清晰翼模糊、多鸟不同景深、逆光、高度锐化、不同相机 JPEG、旋转图、同名文件、断网后恢复。测试不只是对图片人工加模糊。

## 10. RAW 后续完整范围

先设计媒体读取接口但不在首版接入 RAW。后续至少覆盖：相机格式与解码支持、RAW+JPEG 配对、预览质量分级、色彩/方向、全分辨率区域映射、可重复显影参数、缓存空间、评分可比性、成对选片/恢复、XMP/元数据边界和安装包依赖。

rawpy 可作为候选，内嵌 JPEG 与 RAW 显影结果必须标明来源；不能只加扩展名扫描就宣布支持 RAW。[rawpy 文档](https://letmaik.github.io/rawpy/api/rawpy.RawPy.html)。
